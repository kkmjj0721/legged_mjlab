### 0.2 推荐实现顺序与依赖关系

建议按下面的单向依赖实现，不要先从环境 façade 或 registry 反推任务逻辑：

`纯 Config schema → Asset/MJCF（机器人固有传感器）→ Scene/task compiler（SceneCfg.sensors）→ MDP terms → ObservationManager/Env`

这里同时存在一条“配置组装”关系：task compiler 把 Config、Asset、SceneCfg.sensors
和 MDP term 绑定成 `ManagerBasedRlEnvCfg` 及 RL 配置，之后才交给 Env/registry/RSL-RL。
所以“传感器在哪里定义”和“传感器数据在哪里被读取”不能合并成一个 Asset 字段。
机器人固有的 IMU、关节编码器或力/力矩传感器适合跟随 asset/MJCF；依赖 terrain、接触匹配、
ray pattern、相机渲染设置或 actor/critic 选择的传感器不能泛化为“全部放进 asset”。

| 层 | 职责边界 | 主要产物 |
| --- | --- | --- |
| Config schema | 只保存任务参数、默认值和覆盖结构；不导入 `mujoco`、`EntityCfg`、MDP term 或 runner | `Go2VelocityCfg`、`Go2VelocityCfgPPO` |
| Asset/MJCF | 编译 robot XML/MJCF、`MjSpec`、actuator、mount site/body/camera 和机器人固有原生 sensor；不实现 observation/reward/termination/event | `EntityCfg`、稳定的 sensor 名称与物理接口 |
| Scene/task compiler | 组合 Asset 与场景，注册依赖场景的 `SceneCfg.sensors`，配置 `SensorCfg` 自身的内部缓存，再绑定 MDP 和 manager config；不配置 observation history | `RayCastSensorCfg`、`ContactSensorCfg`、`CameraSensorCfg` 或必要的 Python `SensorCfg` |
| MDP terms | 从 `env.scene[name].data` 读取数据，完成 frame/unit 转换并实现 observation、reward、termination、event term；不解析 XML | 面向 manager 的 term 函数或 term 配置 |
| ObservationManager/Env | 按 actor/critic 和 term 顺序计算、拼接并处理 noise、clip、scale、delay、observation history（用于堆叠 policy 输入），输出最终观测 | 最终 observation dict/tensor、reward、done 和 info |

当前仓库仍不存在 Go2 velocity 的 sensor/task/MDP/compiler 实现；后文代码均保持建议模板、未执行/未验证状态。上表描述的是目标拆分和依赖关系，不是当前工作区已有实现。

## 1. 路径工具

文件：`legged_mjlab/utils/paths.py`

```python
import os
from pathlib import Path


def project_root() -> Path:
    """Return the source checkout root.

    The editable source layout is:

        <project>/legged_mjlab/utils/paths.py

    Therefore ``parents[2]`` is the repository root.  An explicit environment
    variable is supported for deployment or a packaged checkout.
    """

    override = os.environ.get("LEGGED_MJLAB_ROOT")
    if override:
        root = Path(override).expanduser().resolve()
    else:
        root = Path(__file__).resolve().parents[2]

    if not root.exists():
        raise FileNotFoundError(f"Project root does not exist: {root}")
    return root


PROJECT_ROOT = project_root()
RESOURCE_ROOT = PROJECT_ROOT / "resources"
ROBOT_RESOURCE_ROOT = RESOURCE_ROOT / "robots"


def resource_path(*parts: str) -> Path:
    """Resolve a project resource and fail early when it is missing."""

    path = RESOURCE_ROOT.joinpath(*parts).resolve()
    if not path.exists():
        raise FileNotFoundError(f"Resource does not exist: {path}")
    return path
```

不要使用 `Path.cwd()`、`from src import SRC_PATH` 或依赖当前 shell 的工作目录。当前
`unitree_rl_mjlab` 的 `src/assets/robots/*_constants.py` 使用了 `SRC_PATH`；迁移时应把

## 3. 配置声明层

文件：`legged_mjlab/envs/base/base_config.py`

本节只定义配置 schema 和参数默认值。纯配置声明层不得导入 `mujoco`、`EntityCfg`、任何 MDP term 或 runner，也不负责创建 `ManagerBasedRlEnvCfg`；资产、MDP 和官方配置对象的组装属于第 4–6 节的后续边界。下面两个代码块是当前工作区代码观察，代码本身已存在；它们不等于完整任务、环境或训练链路已经实现。

这是 `legged_gym` 配置体验的关键。任务配置用嵌套 class 继承公共字段；实例化时递归把
嵌套 class 变成对象，所以训练入口可以直接写 `cfg.env.num_envs = 8192`。

```python
import inspect
from copy import deepcopy
from functools import partial
from pathlib import Path


class BaseConfig:
    def __init__(self) -> None:
        self.init_member_classes(self)

    @staticmethod
    def init_member_classes(obj: object) -> None:
        for key in dir(obj):
            if key == "__class__":
                continue
            value = getattr(obj, key)
            if inspect.isclass(value):
                instance = value()
                setattr(obj, key, instance)
                BaseConfig.init_member_classes(instance)
            elif isinstance(value, (dict, list, set)):
                setattr(obj, key, deepcopy(value))
```

前面的 `legged_mjlab/envs/base/legged_mjlab_config.py` 只承载配置父类声明；当前源文件没有 `ManagerBasedRlEnvCfg`、`clone_env_cfg` 或 `make_play_cfg` 这些函数。下面代码只是未来建议的 compiler/config-override helper 模板，不应复制回纯 config schema 文件。

```python
"""Only generic configuration helpers belong in the base package."""

from copy import deepcopy
from functools import partial
from pathlib import Path
from typing import TYPE_CHECKING

from mjlab.envs import ManagerBasedRlEnvCfg


def clone_env_cfg(cfg: ManagerBasedRlEnvCfg) -> ManagerBasedRlEnvCfg:
    """Deep-copy an environment config before applying task-local overrides."""

    return deepcopy(cfg)


def make_play_cfg(
    cfg: ManagerBasedRlEnvCfg,
    *,
    episode_length_s: float = 1.0e9,
) -> ManagerBasedRlEnvCfg:
    """Create a conservative evaluation copy.

    Task-specific code can add additional overrides after this function.  The
    function does not know about AMP, motion files, robot names or rewards.
    """

    play_cfg = clone_env_cfg(cfg)
    play_cfg.episode_length_s = episode_length_s

    for group in play_cfg.observations.values():
        group.enable_corruption = False

    play_cfg.curriculum = {}
    play_cfg.events.pop("push_robot", None)
    return play_cfg
```

### 4.1 传感器分支：固有硬件随 asset，运行时依赖由 Scene 注册

> 状态边界：`go2.xml` 中的 IMU/MuJoCo sensor 是当前资源事实；`SceneCfg.sensors` 注册、MDP
> 读取和 ObservationManager 处理是未来架构模板，当前 `legged_mjlab` 没有这条运行时接线。
> 以下内容均为未来模板/未执行/未验证，除非句子明确标为 XML 代码观察。

结论先行：把机器人固有传感器写进 asset 的 MJCF，并随实体导入，是稳定而且可复用的做法；
但“所有传感器都放进 asset”不能作为通用规则。IMU、关节编码器、关节力/力矩等描述机器人
自身硬件的传感器可以随 XML 定义；terrain scan、接触匹配、任务相机、ray pattern 以及
actor/critic 选择则依赖场景或任务，应由 task compiler 的 `SceneCfg.sensors` 注册；这只决定
传感器注册，不决定 ObservationManager 的 observation history。

这里要区分两件事：MJCF 负责模型中有什么，以及它的坐标系、单位、稳定名称和原始 shape；
Scene 负责这些传感器何时创建、初始化、更新和 reset，以及任务额外需要哪些运行时传感器。
还要区分两种 history：`SensorCfg` 自身的缓存（例如 `ContactSensorCfg.history_length`，用于
接触数据或传感器内部的 force history）属于 Scene/task 层；`ObservationManager` 的
observation history 才用于堆叠 policy 输入。Scene/task 层只配置前者，actor/critic、noise、
delay 和 observation history 等观测处理归 ObservationManager。
参考的 Scene API 形状是 `SceneCfg.sensors` 保存 `SensorCfg`，由 Scene 在运行时执行
`build`、`edit_spec`、初始化和更新，再包装附加实体 XML 中的 MuJoCo sensor；这只是架构
解释和待核验的版本参考，不是当前 `legged_mjlab` 已存在的 `Scene` 实现或验证结果。

| 层 | 负责什么 | 明确不负责什么 |
| --- | --- | --- |
| Asset/MJCF | robot-mounted `site`/`body`/camera mount；MuJoCo 原生 `gyro`、`accelerometer`、`joint*`、`force`/`torque` 等 sensor；稳定名称、挂载坐标系、单位和输出 shape | actor/critic 选择、noise、delay、observation history、reward、termination 和任务权重 |
| Scene/task/compiler | 在 `SceneCfg.sensors` 中注册 `RayCastSensorCfg`、`ContactSensorCfg`、`CameraSensorCfg` 和必要的 Python `SensorCfg`；配置 terrain/contact matching、ray pattern、以及 SensorCfg 自身的内部缓存（例如 `ContactSensorCfg.history_length`），并接通运行时生命周期 | 不把任务选择塞进 asset；可以引用 asset 的 body/site/name，但不修改 asset XML 的物理定义；不配置 actor/critic 的 observation history、noise 或 delay。`RayCastSensorCfg`/`ContactSensorCfg` 是 Python 场景配置，不是 MJCF 内容 |
| MDP | 从 `env.scene[name].data` 读取原始数据，完成 frame/unit 转换，返回 observation/reward/termination term 的约定 batch shape | 不创建 sensor、不解析 XML、不负责 Scene 注册或 observation 拼接 |
| ObservationManager/config | 固定 term 顺序、actor/critic 分组、noise、clip、scale、delay、observation history（用于堆叠 policy 输入）、拼接方式和最终维度 | 不决定机器人 XML 中是否存在某个固有硬件；不替代 MDP 对 frame/unit 的解释 |

未来模板/未实现：如果传感器确实是机器人固有硬件，可以把 Python `Sensor`/`SensorCfg` 的实现文件和挂载点

```python
"""Task-specific MDP terms for Unitree Go2 velocity tracking."""

from typing import TYPE_CHECKING

import torch

from mjlab.entity import Entity
from mjlab.managers.scene_entity_config import SceneEntityCfg

if TYPE_CHECKING:
    from mjlab.envs import ManagerBasedRlEnv


_DEFAULT_ASSET_CFG = SceneEntityCfg("robot")


def base_ang_vel(
    env: "ManagerBasedRlEnv",
    asset_cfg: SceneEntityCfg = _DEFAULT_ASSET_CFG,
) -> torch.Tensor:
    """Return base angular velocity in body coordinates."""

    asset = env.scene[asset_cfg.name]
    value = asset.data.root_link_ang_vel_b
    assert value.ndim == 2 and value.shape[-1] == 3
    return value


def track_linear_velocity(
    env: "ManagerBasedRlEnv",
    *,
    command_name: str,
    std: float,
    asset_cfg: SceneEntityCfg = _DEFAULT_ASSET_CFG,
) -> torch.Tensor:
    """Reward XY velocity tracking and penalize vertical base velocity."""

    asset: Entity = env.scene[asset_cfg.name]
    command = env.command_manager.get_command(command_name)
    assert command is not None, f"Command {command_name!r} is not registered."

    actual = asset.data.root_link_lin_vel_b
    error_xy = torch.sum(torch.square(command[:, :2] - actual[:, :2]), dim=1)
    error_z = torch.square(actual[:, 2])
    return torch.exp(-(error_xy + 2.0 * error_z) / (std**2))


def track_yaw_velocity(
    env: "ManagerBasedRlEnv",
    *,
    command_name: str,
    std: float,
    asset_cfg: SceneEntityCfg = _DEFAULT_ASSET_CFG,
) -> torch.Tensor:
    """Reward yaw velocity tracking and discourage lateral spin."""

    asset: Entity = env.scene[asset_cfg.name]
    command = env.command_manager.get_command(command_name)
    assert command is not None, f"Command {command_name!r} is not registered."

    actual = asset.data.root_link_ang_vel_b
    error_yaw = torch.square(command[:, 2] - actual[:, 2])
    error_xy = torch.sum(torch.square(actual[:, :2]), dim=1)
    return torch.exp(-(error_yaw + 0.05 * error_xy) / (std**2))


def upright_penalty(
    env: "ManagerBasedRlEnv",
    asset_cfg: SceneEntityCfg = _DEFAULT_ASSET_CFG,
) -> torch.Tensor:
    """Return squared projected gravity in the robot XY plane."""

    asset: Entity = env.scene[asset_cfg.name]
    gravity_b = asset.data.projected_gravity_b
    return torch.sum(torch.square(gravity_b[:, :2]), dim=1)
```

每个 term 必须返回形状 `[num_envs]` 的 tensor。不能在 term 内部做 batch mean，也不能在
term 内部调用 `sim.forward()`、`sim.step()` 或 reset。

```python
"""Thin project facade around mjlab's official task registry."""

from copy import deepcopy
from pathlib import Path
from typing import Any, Callable, NamedTuple

from legged_mjlab.integrations.rsl_rl_runner import make_runner
from mjlab.envs import ManagerBasedRlEnv, ManagerBasedRlEnvCfg
from mjlab.rl import RslRlBaseRunnerCfg
from mjlab.tasks.registry import (
    list_tasks as _list_tasks,
    register_mjlab_task,
)

class TaskSpec(NamedTuple):
    env_cls: type[ManagerBasedRlEnv]
    cfg_cls: type
    ppo_cfg_cls: type
    env_cfg_factory: Callable[..., ManagerBasedRlEnvCfg]
    rl_cfg_factory: Callable[..., RslRlBaseRunnerCfg]
    validator: Callable[[Any, Any], None] | None = None
    runner_cls: type | None = None


_TASKS: dict[str, TaskSpec] = {}


def register_task(
    *,
    task_id: str,
    spec: TaskSpec,
) -> None:
    """Register task class/config classes and official compiled defaults."""

    if task_id in _TASKS:
        raise ValueError(f"Task is already registered: {task_id}")

    env_cfg = spec.env_cfg_factory(spec.cfg_cls(), play=False)
    play_env_cfg = spec.env_cfg_factory(spec.cfg_cls(), play=True)
    rl_cfg = spec.rl_cfg_factory(spec.ppo_cfg_cls())
    register_mjlab_task(
        task_id=task_id,
        env_cfg=env_cfg,
        play_env_cfg=play_env_cfg,
        rl_cfg=rl_cfg,
        runner_cls=spec.runner_cls,
    )
    _TASKS[task_id] = spec


def list_tasks() -> list[str]:
    """Return task ids from the official registry."""

    return list(_list_tasks())


def make_task_config(task_id: str) -> Any:
    """Return a fresh legged-gym-style task Config instance."""

    return _TASKS[task_id].cfg_cls()


def make_task_ppo_config(task_id: str) -> Any:
    """Return a fresh task ConfigPPO instance."""

    return _TASKS[task_id].ppo_cfg_cls()


def validate_task_config(task_id: str, cfg: Any, ppo_cfg: Any) -> None:
    validator = _TASKS[task_id].validator
    if validator is not None:
        validator(cfg, ppo_cfg)


def make_task_rl_cfg(
    task_id: str,
    ppo_cfg: Any | None = None,
) -> RslRlBaseRunnerCfg:
    """Compile a task ConfigPPO or use the registered default."""

    if ppo_cfg is None:
        return _TASKS[task_id].rl_cfg_factory(_TASKS[task_id].ppo_cfg_cls())
    return _TASKS[task_id].rl_cfg_factory(ppo_cfg)


def get_env_class(task_id: str) -> type[ManagerBasedRlEnv]:
    try:
        return _TASKS[task_id].env_cls
    except KeyError as exc:
        raise KeyError(
            f"No project environment class registered for {task_id!r}. "
            "Import legged_mjlab.envs before querying tasks."
        ) from exc


def make_env(
    task_id: str,
    *,
    device: str = "cpu",
    render_mode: str | None = None,
    cfg: Any | None = None,
    play: bool = False,
) -> ManagerBasedRlEnv:
    """Construct the project task from a user-facing Config instance."""

    task_cfg = cfg if cfg is not None else make_task_config(task_id)
    if play:
        # The environment class may expose a play-specific constructor in a
        # later version; for now compile with the task factory before create.
        task_cfg = deepcopy(task_cfg)
    env_cls = get_env_class(task_id)
    if play:
        compiled_cfg = _TASKS[task_id].env_cfg_factory(task_cfg, play=True)
        return env_cls(
            cfg=task_cfg,
            device=device,
            render_mode=render_mode,
            compiled_cfg=compiled_cfg,
        )
    return env_cls(cfg=task_cfg, device=device, render_mode=render_mode)


def make_task_runner(
    task_id: str,
    env: ManagerBasedRlEnv,
    *,
    log_dir: str | Path | None = None,
    device: str = "cpu",
    train_cfg: RslRlBaseRunnerCfg | None = None,
    ppo_cfg: Any | None = None,
):
    """Compile CfgPPO if needed, then create the official/default runner."""

    if train_cfg is not None:
        rl_cfg = train_cfg
    else:
        rl_cfg = make_task_rl_cfg(task_id, ppo_cfg)
    return make_runner(
        task_id,
        env,
        rl_cfg,
        log_dir=log_dir,
        device=device,
    )
```

```python
"""Create a runner from mjlab's task registry."""

from dataclasses import asdict, is_dataclass
from pathlib import Path

from mjlab.envs import ManagerBasedRlEnv
from mjlab.rl import MjlabOnPolicyRunner, RslRlBaseRunnerCfg
from mjlab.tasks.registry import load_runner_cls

from .rsl_rl_wrapper import wrap_for_rsl_rl


def make_runner(
    task_id: str,
    env: ManagerBasedRlEnv,
    cfg: RslRlBaseRunnerCfg,
    *,
    log_dir: str | Path | None = None,
    device: str = "cpu",
):
    """Return ``(runner, wrapped_env)`` for a registered task."""

    wrapped_env = wrap_for_rsl_rl(env, cfg)
    runner_cls = load_runner_cls(task_id) or MjlabOnPolicyRunner
    if not is_dataclass(cfg):
        raise TypeError(
            f"Expected a dataclass RSL-RL config, got {type(cfg).__name__}"

    runner = runner_cls(
        wrapped_env,
        train_cfg=asdict(cfg),
        log_dir=None if log_dir is None else str(log_dir),
        device=device,
    )
    return runner, wrapped_env
```

```python
import argparse
from pathlib import Path

import legged_mjlab.envs  # noqa: F401
from legged_mjlab.utils.config_override import apply_overrides
from legged_mjlab.utils.task_registry import (
    make_env,
    make_task_config,
    make_task_ppo_config,
    make_task_rl_cfg,
    make_task_runner,
    validate_task_config,
)


def parse_args() -> argparse.Namespace:
    parser = argparse.ArgumentParser(description="Train a registered legged-mjlab task.")
    parser.add_argument("task", help="Registered task id")
    parser.add_argument("--device", default="cpu")
    parser.add_argument("--num-envs", type=int, default=None)
    parser.add_argument("--max-iterations", type=int, default=None)
    parser.add_argument(
        "--set",
        dest="set_values",
        action="append",
        default=[],
        metavar="FIELD=VALUE",
        help="Override a task config field, e.g. env.num_envs=8192",
    )
    parser.add_argument("--log-dir", default="logs/rsl_rl")
    return parser.parse_args()


def main() -> None:
    args = parse_args()
    cfg = make_task_config(args.task)
    ppo_cfg = make_task_ppo_config(args.task)

    if args.num_envs is not None:
        cfg.env.num_envs = args.num_envs
    if args.max_iterations is not None:
        ppo_cfg.runner.max_iterations = args.max_iterations

    apply_overrides(cfg, ppo_cfg, args.set_values)
    validate_task_config(args.task, cfg, ppo_cfg)

    env = make_env(
        args.task,
        device=args.device,
        cfg=cfg,
    )
    # The registered task compiler maps CfgPPO into RSL-RL.
    rl_cfg = make_task_rl_cfg(args.task, ppo_cfg)

    log_dir = Path(args.log_dir) / rl_cfg.experiment_name
    runner, wrapped_env = make_task_runner(
        args.task,
        env,
        device=args.device,
        log_dir=log_dir,
        train_cfg=rl_cfg,
    )

    try:
        runner.learn(
            num_learning_iterations=rl_cfg.max_iterations,
            init_at_random_ep_len=True,
        )
    finally:
        wrapped_env.close()


if __name__ == "__main__":
    main()
```

### 16.2 legged_gym 调用链

legged_gym 常见的配置层是递归 class：外层配置继承内层配置，子类通过继承覆盖少量字段。
这使得机器人、地形、奖励和训练参数能够按层叠加，但也容易让最终值隐藏在多级 class 中。

典型环境链路可以写成：

`base_config` 递归 class → `LeggedRobot` 初始化 → `step` → `post_physics_step` → `check_termination` → `reset_idx`。

典型任务工厂链路可以写成：

`task_registry.register` → `get_cfgs` → `make_env` → `make_alg_runner` → `train` 或 `play`。

`LeggedRobot.step` 通常接收 `[N, A]` action，按 decimation 推进仿真，然后调用 `post_physics_step`。

`post_physics_step` 汇总观测、奖励、终止标志、超时标志和 episode 统计，并准备下一次 policy 输入。

`check_termination` 负责碰撞、姿态、越界和时间限制等条件；超时应与真正 terminated 分开。

`reset_idx` 只重置指定环境，重新采样初始状态、episode 计数、历史缓存和需要清零的统计量。

`task_registry.get_cfgs` 返回环境配置和训练配置；读取后应避免把全局可变对象直接泄露给多个任务。

`task_registry.make_env` 创建环境与必要 wrapper；`make_alg_runner` 再把环境契约交给算法 runner。

`train` 连接环境、RSL wrapper 和训练 runner；`play` 则复用环境构造，但关闭随机化或使用评估策略。

四个本地仓库的迁移观察如下。

| 仓库 | 重点观察 | 迁移时的边界 |
| --- | --- | --- |
| `go2_rl_gym` | CTS、MoE、history、latent，以及它们如何进入 actor/critic 输入 | 将策略特征作为明确的 `[N,H,D]`、`[N,L]` 契约，不把隐藏状态塞进 physics loop |
| `HIMLoco` | `HIMEstimator`、`HIMActorCritic`、`HIMPPO`、`HIMOnPolicyRunner` | estimator、actor、loss、storage 要拆成可测试 adapter，不能假定普通 PPO 自动支持 HIM |
| `My_unitree_go2_gym` | 任务资产、关节顺序、动作缩放和动作映射 | 先固定 Entity/Actuator 命名与 `[N,A]` 映射，再连接控制器 |
| `uw-himloco` | HIM、部署导出、sim2sim 的接口分界 | 导出模型和部署输入必须与训练 history、latent、归一化统计一致 |

算法实现建议放在 `rsl_rl adapter` 中。

环境只提供标准化的 observation、action、reward、terminated、truncated 和 info。

HIM、AMP 或 MoE 的 rollout、storage、loss 和 runner 扩展不应反向污染基础环境的 physics state。

推断：保留 `train/play` 外观有利于迁移脚本，但注册表与 runner 之间必须通过稳定 adapter 连接。

### 16.3 mjlab 双层架构

mjlab 的底层是 MuJoCo 模型与数据层：`MjSpec` 描述并编译模型，`MjModel` 保存编译后的静态模型，`MjData` 保存运行时状态。

场景层再把实体和传感器组织起来，包括 `Entity`、`Actuator`、`Sensor` 与 `Scene`。

上层是 manager-based RL：`ManagerBasedRlEnv` 承载生命周期，`ManagerBasedRlEnvCfg` 描述配置。

常见 manager 责任包括 `Observation`、`Action`、`Reward`、`Termination`、`Event`、`Command`、`Curriculum` 与 `Metrics`。

底层负责可编译资产和物理数据，上层负责 term 组合和 RL 语义；两层之间用明确的批量张量契约连接。

term lifecycle 应按 reset、pre-step、physics decimation、post-step、metric 汇总的顺序设计。

Observation term 读取允许的状态快照并返回 batch tensor；Reward term 读取状态和 action 并返回 `[N]`。

Termination term 返回 terminated 或 truncated 的布尔 batch；Event term 只在声明的生命周期触发。

Command 和 Curriculum 改变目标或采样分布，Metrics 只汇总可观察量，不应偷偷修改物理状态。

配置建议使用 dataclass，并在边界处转换为只读或受控的字典，避免递归 class 的隐式覆盖继续扩散。

每个 manager term 都应记录输入键、输出 shape、device、坐标系、单位和触发时机。

registry 只负责从任务名找到唯一的 EnvCfg、资产构造器和训练配置，不负责保存跨任务运行时状态。

RSL wrapper 将 manager 环境转换为 rsl_rl 需要的向量环境接口；runner 只通过 wrapper 访问 rollout 数据。

不能把 Isaac Gym 的 physics loop 原样搬进 mjlab。

不能假定 `obs_buf`、`rew_buf`、`reset_buf` 是唯一或固定的状态容器；应由 observation、reward、termination manager 组合产生对应结果。

不能使用依赖当前工作目录的相对 `src` 导入；入口脚本应使用已安装 package 或稳定的项目根路径。

`unitree_rl_mjlab` 可作为任务注册、资产和 RSL 接口的对照样本。

`AMP_mjlab` 可作为 AMP 任务、动作与运动数据边界的对照样本，但其判别器训练复杂度不能被普通 PPO 契约掩盖。

对比结论：前者更适合观察 mjlab 任务落地和 runner 接线，后者更适合观察 motion/AMP 扩展；两者都不能替代版本核验。

```python
def base_height_reward(base_pos_world: Tensor, target_height_m: float) -> Tensor:
    """输入 [N, D]，这里 D=3；输出 [N]，单位为无量纲奖励。"""
```

```python
from dataclasses import dataclass
import torch
from torch import Tensor


@dataclass
class HistoryCfg:
    horizon: int = 5
    feature_dim: int = 48


class History:
    def __init__(self, num_envs: int, cfg: HistoryCfg, device: str = "cpu"):
        self.data = torch.zeros(
            (num_envs, cfg.horizon, cfg.feature_dim),
            dtype=torch.float32,
            device=device,
        )

    def append(self, current: Tensor) -> Tensor:
        # current: [N, D]；raw buffer data: [N, H, D]，current-first/newest-first；
        # MLP flatten 是 [N, H*D]，rollout storage 是 [T, N, ...]，三者 layout 不同。
        # N=1 仍保留 batch 维，不能 squeeze；frame/unit 由 feature schema 固定。
        assert current.ndim == 2 and current.shape[-1] == self.data.shape[-1]
        self.data = torch.cat((current[:, None, :], self.data[:, :-1]), dim=1)
        return self.data

    def actor_input(self) -> Tensor:
        # raw buffer 保持 [N, H, D]；MLP 输入才展平为 [N, H*D]，不能与
        # rollout storage 的 [T, N, ...] 混用；N=1 也不能 squeeze batch 维。
        return self.data.flatten(start_dim=1)

    def critic_input(self, privileged: Tensor) -> Tensor:
        assert privileged.ndim == 2 and privileged.shape[0] == self.data.shape[0]
        return torch.cat((self.actor_input(), privileged), dim=-1)


def amp_history(history: Tensor) -> Tensor:
    """AMP 入口保留 [N, H, D]，不要把 batch=1 特判成 [H, D]。"""
    assert history.ndim == 3
    return history
```

```python
from dataclasses import dataclass
from typing import Callable, Any


@dataclass(frozen=True)
class TrainCfg:
    runner_name: str = "rsl_rl"
    seed: int = 1


class TaskRegistry:
    def __init__(self):
        self._items: dict[str, tuple[Any, TrainCfg, Callable[..., Any]]] = {}

    def register(self, name: str, env_cfg: Any, train_cfg: TrainCfg, factory: Callable[..., Any]):
        if name in self._items:
            raise KeyError(f"duplicate task: {name}")
        self._items[name] = (env_cfg, train_cfg, factory)

    def get_cfgs(self, name: str) -> tuple[Any, TrainCfg]:
        env_cfg, train_cfg, _ = self._items[name]
        return env_cfg, train_cfg

    def make_env(self, name: str, **kwargs: Any) -> Any:
        env_cfg, _, factory = self._items[name]
        return factory(env_cfg, **kwargs)

    def make_alg_runner(self, name: str, env: Any, **kwargs: Any) -> Any:
        _, train_cfg, _ = self._items[name]
        from legged_mjlab.integrations.runner import RslRlRunner  # 需按版本调整
        return RslRlRunner(env=env, train_cfg=train_cfg, **kwargs)


task_registry = TaskRegistry()


def train(task_name: str, num_envs: int = 2) -> None:
    env_cfg, _ = task_registry.get_cfgs(task_name)
    env = task_registry.make_env(task_name, num_envs=num_envs, device="cpu")
    runner = task_registry.make_alg_runner(task_name, env)
    runner.learn()


def play(task_name: str, checkpoint: str) -> None:
    env = task_registry.make_env(task_name, eval_mode=True)
    runner = task_registry.make_alg_runner(task_name, env, checkpoint=checkpoint)
    runner.play()
```

### 16.6 渐进验证

以下顺序用于缩小故障面；每一步都必须记录观察点和停止条件。

1. `plane + 2 env reset/zero step`：观察 MjModel/MjData 是否创建、两个环境的 batch shape 是否保持、zero action 是否有限。
   停止条件：asset compile 失败、reset 非有限、`[2, ...]` 被压成单环境或 terminated/truncated 语义不明。
2. 单独修改一个 reward 或 observation term：观察 term 输入输出 shape、device、frame、unit 和梯度/数值范围。
   停止条件：reward 广播、NaN/Inf、单位混用，或修改一项却影响未声明的状态。
3. 加入 terrain 和 domain randomization：观察 reset event、地形索引、随机种子和 CPU 小 batch 的重复性。
   停止条件：scene 资产编译不稳定、随机化跨环境串扰、碰撞或高度状态坐标系未定义。
4. 加入 history 和 privileged observation：观察 actor/critic 是否分别得到 `[N,H,D]`、`[N,P]`，batch=1 是否仍保留 batch 维。
   停止条件：history 首尾方向错误、critic 输入泄露给 actor、导出输入维度不一致。
5. 最后接入 AMP：观察 motion loader、AMP group、discriminator transition、normalization 和 replay 的 shape/统计量。
   停止条件：判别器 transition 与环境 transition 不同构、AMP loss 未隔离、未能复现有限的短跑指标。

每一步都应有最小测试和可复现 seed，失败时停在当前层，不向后叠加新变量。

### 16.7 HIM/AMP adapter

HIM adapter 的最小数据契约应显式写出：`obs_history [N,H,D]`、`privileged [N,P]`、`latent [N,L]`。

actor 输入可以是当前观测、history 展平结果和 latent 的拼接，但拼接顺序必须进入 checkpoint metadata。

critic 可以额外使用 privileged；部署 actor 不应依赖训练时不可获得的 privileged 字段。

HIMEstimator 从 history 估计 latent 时，训练阶段可保留 encoder loss，推理阶段应有明确的 detach 边界。

`HIMActorCritic` 只管理网络结构和 forward；`HIMPPO` 管理 policy/value/encoder loss 的组合。

`HIMOnPolicyRunner` 管理 rollout、storage、更新顺序和日志；这些类应在 rsl_rl adapter 层，而非基础 env 层。

storage 至少保存 actor observation、critic observation、action、reward、terminated、truncated、value、log probability、history 和 latent 所需字段。

AMP adapter 还需要 motion loader、AMP group、discriminator transition、custom runner/config、replay 和 normalization。

discriminator transition 要固定帧窗口、状态顺序、参考 motion 的 unit 和是否 detach policy 生成的样本。

AMP replay 的归一化统计必须与训练和部署的 observation schema 匹配，不能复用未经确认的 PPO 统计量。

custom runner/config 应把 discriminator optimizer、AMP 权重、motion batch 和 replay 容量作为显式配置。

当前 `legged_mjlab` 未实现 HIM/AMP adapter。

因此本节是接口设计和迁移边界，不是现有功能清单，也不是运行结果。

## 21. HIM 与 AMP 的 adapter 协议

核心环境只负责稳定的 observation groups、commands、reward/termination terms 和 transition；算法 adapter 负责网络、storage、loss、normalization、checkpoint。不要把 HIM/AMP 逻辑塞回 `LeggedMjlabEnv`。

### 21.1 HIM

代码观察：HIMLoco 的 `HIMEstimator`、`HIMActorCritic`、`HIMPPO`、`HIMOnPolicyRunner` 分别承担 encoder/actor-critic/优化/storage/runner。history → latent → actor 是跨包契约：

本地配置观察：HIMLoco 的 `num_one_step_obs=45`、`history=6`、estimated velocity 为 `3`、latent 为 `16`；因此 actor 输入为 `45+3+16=64`。current frame 位于 history 首位。HIM storage 应保留 `next_privileged_observations`；latent 是否存储取决于 adapter contract，不能把这些维度或 latent storage 方式写成泛化常量。

- student history：`obs_history`，shape `[N,H,D]`，device 与 actor 相同；
- teacher privileged observation：shape `[N,P]`，训练可用但部署 actor 不应依赖；
- encoder output latent：shape `[N,L]`；
- actor input：concat(`current_obs [N,D]`、`estimated_velocity [N,V]`、`latent [N,L]`)，shape `[N,D+V+L]`；
- rollout transition：obs、critic_obs、actions、rewards、dones/timeout、obs_history、teacher latent/privileged target，必须按 `[T,N,...]` 或实际 storage layout 明确。

设计建议：student encoder 输入在计算 teacher loss 时 detach 的方向要写在 adapter 中；teacher encoder、student encoder、latent loss 的 optimizer ownership 不能由环境猜测。batch=1 时保持 `[1,H,D]` 和 `[1,L]`，并检查 history reset 与跨 episode 泄漏。

### 21.2 AMP

AMP adapter 至少有 motion loader、reference/motion observation group、discriminator transition、AMP reward、replay/preload buffer、normalization、custom runner/config。环境只提供 policy observation、AMP observation `[N,M]`、task reward 和 episode termination；独立 runner 接收 policy transition 和 expert transition。

代码观察：AMP_mjlab 的本地结构含 `src/tasks/amp_loco/amp_env_cfg.py`、`src/tasks/amp_loco/config/g1/rl_cfg.py`、`src/tasks/amp_loco/config/g1/__init__.py` 与 `src/tasks/amp_loco/rl/runner.py`；它通过 `register_mjlab_task(... runner_cls=AMPOnPolicyRunner)` 注册专用 runner，并扩展 AMP runner config。这里是推断：这些特化应以独立 rsl_rl 包或 adapter 依赖存在，不应成为 core legged_mjlab 的必选依赖。

进一步的本地配置观察：AMP_mjlab 的 G1 `body_names=14`；每个 body 的 `body_pos 3 + body_ori 6 + body_lin_vel 3 + body_ang_vel 3 = 15` 维，因此 `M=14*15=210`，discriminator pair concat 为 `[N,420]`。这是该 AMP_mjlab 本地 config 的推导，不是通用 AMP 常量；`AMP_mjlab/setup.py` 锁定 `mjlab==1.2.0`。

### 21.3 失败条件

motion file 不存在、body/anchor 顺序不一致、AMP group shape 不一致、privileged observation 误进入部署 actor、history reset 未清零、normalization/checkpoint 缺失、discriminator transition 与 policy transition 不同 device，均是阻塞项。训练曲线或能启动 runner 不能证明上述合同正确。

未执行/未验证：当前 legged_mjlab 没有完成 HIM/AMP adapter，也没有加载 motion 或运行 discriminator。
