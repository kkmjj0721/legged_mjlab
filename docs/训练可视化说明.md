# 训练实时可视化说明

这份说明只讨论一个问题：直接训练 `him_go2` 时，怎样像 `legged_gym` 一样在启动参数里选择 viewer，并实时看到训练中的 PPO rollout。

本文参考两处代码：

- `/home/kk/github/unitree_rl_mjlab`：参考它的 `auto/native/viser` 参数语义、viewer 后端选择和训练视频设计。
- `/home/kk/legged_mjlab/.venv/lib64/python3.11/site-packages/mjlab`：参考安装版 `mjlab.viewer` 的真实主循环，确认哪些接口能复用，哪些不能直接用于训练。

当前结论：**目标不是训练后回放，而是 `train.py` 训练过程中同步显示正在 rollout 的同一个环境。第一版推荐用 monkey-patch 包装 `env.step()`，这样不用直接改外部 `rsl_rl` runner 源码，也能在每次 PPO rollout step 后刷新 viewer。**

## 1. 目标启动方式

命令风格保持简单：先进入虚拟环境，然后直接 `python` 运行。

```bash
source .venv/bin/activate
```

正常高速训练，不开实时窗口：

```bash
python legged_mjlab/scripts/train.py --task him_go2 --num_envs 4096 --headless
```

训练时打开本地 MuJoCo 原生窗口，适合本机有桌面显示：

```bash
python legged_mjlab/scripts/train.py --task him_go2 --num_envs 1 --viewer native
```

训练时打开 Viser web viewer，适合远程机器或没有桌面窗口：

```bash
python legged_mjlab/scripts/train.py --task him_go2 --num_envs 1 --viewer viser
```

训练时自动选择 viewer：有 `DISPLAY` 或 `WAYLAND_DISPLAY` 时用 `native`，否则用 `viser`。

```bash
python legged_mjlab/scripts/train.py --task him_go2 --num_envs 1 --viewer auto
```

注意：这些是目标语义。当前代码里已经有一部分 viewer 尝试，但还没有完整、可靠地接到训练 step 之后。

| `--video` | 参数存在，适合训练片段录制，但不是实时 viewer | `legged_mjlab/utils/helpers.py` |

当前 `train.py` 里的关键问题是：

```text
runner.viewer = NativeMujocoViewer(env, None)
runner.viewer = ViserPlayViewer(env, None)
runner.learn(...)
```

这还不够，因为：

1. 没有调用 viewer 的 `setup()`，窗口或 web server 不会启动。
2. `HIMOnPolicyRunner.learn()` 没有读取或调用 `runner.viewer`，所以没有同步画面。
3. 传入 `policy=None` 只在“不调用 viewer 自己的 step loop”时成立；如果误调用 `viewer.run()`，会在 `policy(obs)` 处失败。

因此后续实现应该用训练期 viewer hook 包装 `env.step()`，而不是继续只在 `train.py` 里挂 `runner.viewer` 属性。

## 4. 为什么不能直接调用 viewer.run()

安装版 `mjlab.viewer.BaseViewer` 是完整的 play loop，不只是渲染器。

它的主循环大致是：

```text
viewer.run()
  setup()
  while is_running():
    tick()

tick()
  _process_actions()
  _step_physics(dt)
  sync_env_to_viewer()

_step_physics(dt)
  obs = env.get_observations()
  actions = policy(obs)
  env.step(actions)
```

这说明 `NativeMujocoViewer(env, policy).run()` 和 `ViserPlayViewer(env, policy).run()` 都会自己推进环境。它们适合 `play.py`，不适合直接塞进 PPO 训练主循环。

训练时 PPO runner 已经在做这些事：

```text
actions = alg.act(obs, critic_obs)
obs, privileged_obs, rewards, dones, infos, ... = env.step(actions)
alg.process_env_step(...)
```

所以训练实时 viewer 不能调用：

- `viewer.run()`：会进入完整 viewer 主循环。
- `viewer.tick()`：会调用 `_step_physics()`。
- `viewer._step_physics()`：会自己 `env.step(actions)`。

训练期只能复用 viewer 的这些能力：

- `setup()`：创建 native 窗口或 viser server。
- `sync_env_to_viewer()`：把当前训练环境状态同步到画面。
- `is_running()`：判断 native 窗口是否还存在。
- `close()`：训练结束或异常退出时释放资源。

## 5. 推荐实现方案：monkey-patch env.step

第一版推荐采用 monkey-patch 包装 `env.step()`，而不是修改 `rsl_rl/rsl_rl/runners/him_on_policy_runner.py`。

原因：

- `task_registry.make_env()` 返回的是 runner 实际持有的 wrapped env。
- `HIMOnPolicyRunner.learn()` 每个 rollout step 都调用 `self.env.step(actions)`。
- 如果在 `train.py` 中把这个 env 的 `step` 替换为 `step_with_viewer`，runner 不需要知道 viewer 存在。
- wrapper 的 `__getattr__` 会把 viewer 需要的 `cfg`、`unwrapped`、`device` 等属性转发到底层 env。

推荐调用链：

```text
train.py
  env = make_env(..., render_mode=None)
  runner = make_alg_runner(env=env, ...)
  viewer_hook = TrainingViewerHook(env, backend=args.viewer, ...)
  viewer_hook.setup()

  original_step = env.step
  env.step = step_with_viewer

  runner.learn(...)

step_with_viewer(actions)
  result = original_step(actions)
  viewer_hook.render_if_needed()
  return result
```

这样看到的是训练 runner 正在推进的同一个 env 状态；viewer 不负责动作计算，也不负责物理步进。

## 6. TrainingViewerHook 设计

建议新增文件：

| 文件 | 作用 |
| --- | --- |
| `legged_mjlab/utils/training_viewer.py` | 封装训练期 viewer 后端选择、`setup()`、同步频率和关闭逻辑 |

建议接口：

```text
TrainingViewerHook(env, backend="auto", interval=1, exit_action="continue")
hook.setup()
hook.render_if_needed()
hook.close()
hook.inactive
```

`render_if_needed()` 的规则：

- 可以调用 `viewer.sync_env_to_viewer()`。
- 可以调用 `viewer.is_running()`。
- 不允许调用 `viewer.run()`。
- 不允许调用 `viewer.tick()`。
- 不允许调用 `viewer._step_physics()`。
- native 窗口关闭后，hook 自动变为 inactive，训练继续或按 `viewer_exit` 停止。
- viser 的 `is_running()` 当前总是返回真，所以 viser 关闭/断连不能只靠 `is_running()` 判断；第一版可以允许它随训练进程存在。

建议使用“抛错型 dummy policy”，不要用 `lambda obs: None`：

```python
def _unused_policy(obs):
    raise RuntimeError(
        "TrainingViewerHook must not call viewer.run(), viewer.tick(), "
        "or viewer._step_physics() during training."
    )
```

原因是训练期不应该调用 policy。如果未来有人误调用 `viewer.run()`，抛错型 policy 会立刻暴露问题；`lambda obs: None` 可能让错误更晚才出现。

伪流程：

```text
setup:
  resolved = resolve_viewer_backend(auto/native/viser)
  viewer = NativeMujocoViewer(env, _unused_policy) 或 ViserPlayViewer(env, _unused_policy)
  viewer.setup()

render_if_needed:
  if inactive: return
  step_counter += 1
  if step_counter % interval != 0: return
  if backend == native and not viewer.is_running():
    inactive = True
    if exit_action == stop: stop training
    return
  viewer._step_count = step_counter
  viewer._stats_frames += 1
  viewer.sync_env_to_viewer()

close:
  viewer.close()
```

`viewer._step_count` 和 `_stats_frames` 是 private 字段，但如果不走 `BaseViewer.run()`，这些状态不会自动更新；第一版可以只更新 step count，FPS/RTF 不准确也可以接受。

### 7.1 `legged_mjlab/utils/training_viewer.py`

```python
import os
import sys


def _unused_policy(obs):
    raise RuntimeError(
        "TrainingViewerHook must not call viewer.run(), viewer.tick(), "
        "or viewer._step_physics() during training."
    )


class TrainingViewerHook:
    def __init__(self, env, backend="auto", interval=1, exit_action="continue"):
        self.env = env
        self.backend = backend
        self.interval = max(1, int(interval))
        self.exit_action = exit_action
        self.viewer = None
        self.inactive = False
        self.step_counter = 0

    def setup(self):
        if self.backend == "auto":
            has_display = bool(os.environ.get("DISPLAY") or os.environ.get("WAYLAND_DISPLAY"))
            self.backend = "native" if has_display else "viser"

        print(f"[INFO] Launching training viewer backend: {self.backend}")

        if self.backend == "native":
            from mjlab.viewer import NativeMujocoViewer
            self.viewer = NativeMujocoViewer(self.env, _unused_policy)
        elif self.backend == "viser":
            from mjlab.viewer import ViserPlayViewer
            self.viewer = ViserPlayViewer(self.env, _unused_policy)
        else:
            raise ValueError(f"Unsupported viewer backend: {self.backend}")

        self.viewer.setup()

    def render_if_needed(self):
        if self.inactive or self.viewer is None:
            return

        self.step_counter += 1
        if self.step_counter % self.interval != 0:
            return

        if self.backend == "native" and not self.viewer.is_running():
            self.inactive = True
            if self.exit_action == "stop":
                print("[INFO] Viewer closed, stopping training.")
                sys.exit(0)
            return

        # Keep overlay step count meaningful when BaseViewer.run() is not used.
        self.viewer._step_count = self.step_counter
        self.viewer._stats_frames += 1
        self.viewer.sync_env_to_viewer()

    def close(self):
        if self.viewer is not None:
            try:
                self.viewer.close()
            except Exception:
                pass
```

### 7.2 `legged_mjlab/scripts/train.py`

```python
"""Command-line entry point for configured RSL-RL training."""

import legged_mjlab.envs
from legged_mjlab.utils.helpers import get_args, update_cfg_from_args
from legged_mjlab.utils.task_registry import task_registry
from legged_mjlab.utils.training_viewer import TrainingViewerHook


def train(args):
    args.play = False
    env_cfg, train_cfg = task_registry.get_cfgs(name=args.task)
    update_cfg_from_args(env_cfg, train_cfg, args)

    if not args.headless and getattr(args, "num_envs", None) is None:
        env_cfg.env.num_envs = 1

    env, _ = task_registry.make_env(name=args.task, args=args, env_cfg=env_cfg)
    runner, train_cfg = task_registry.make_alg_runner(
        env=env, name=args.task, args=args, train_cfg=train_cfg
    )

    viewer_hook = None
    if not args.headless:
        viewer_hook = TrainingViewerHook(
            env=env,
            backend=args.viewer,
            interval=getattr(args, "viewer_interval", 1),
            exit_action=getattr(args, "viewer_exit", "continue"),
        )
        viewer_hook.setup()

        original_step = env.step

        def step_with_viewer(actions):
            result = original_step(actions)
            viewer_hook.render_if_needed()
            return result

        env.step = step_with_viewer

    try:
        runner.learn(
            num_learning_iterations=train_cfg.runner.max_iterations,
            init_at_random_ep_len=True,
        )
    finally:
        if viewer_hook is not None:
            viewer_hook.close()


if __name__ == "__main__":
    args = get_args()
    train(args)
```

## 8. 关键注意事项

- monkey-patch 应该包装 `task_registry.make_env()` 返回的 wrapped env，而不是底层原始 env；runner 持有的是 wrapped env。
- monkey-patch 放在 `make_alg_runner()` 前后都能影响 runner 后续 `self.env.step()`，因为 runner 保存的是同一个 env 对象；第一版建议放在 runner 创建后，避免影响 runner 初始化阶段。
- 不要继续使用 `runner.viewer = ...` 作为主要接口，除非 runner 也被显式修改为消费它。
- `--video` 和 `--viewer` 第一版不建议同时开；实时 viewer 使用 `render_mode=None`，视频录制使用 `render_mode="rgb_array"`。
- viewer GUI 里的暂停、单步、加速按钮第一版不要接入训练控制，否则会破坏 PPO rollout 节奏。
- `native` 需要本机显示环境；SSH 或服务器上优先用 `--viewer viser`。
- 实时训练会明显拖慢训练，建议 `--num_envs 1` 或很小环境数。

## 9. 与 unitree_rl_mjlab 的关系

参考项目 `/home/kk/github/unitree_rl_mjlab` 提供了可复用的 viewer 后端选择逻辑。

`scripts/play.py` 的关键流程是：

```text
load_env_cfg(task_id, play=True)
load_rl_cfg(task_id)
ManagerBasedRlEnv(..., render_mode=None)
RslRlVecEnvWrapper(env, ...)
构造 trained/random/zero policy
根据 viewer=auto/native/viser 选择后端
NativeMujocoViewer(env, policy).run()
或 ViserPlayViewer(env, policy).run()
```

`scripts/train.py` 的关键流程是：

```text
ManagerBasedRlEnv(..., render_mode="rgb_array" if video else None)
video=True 时用 VideoRecorder 包装 env
runner.learn(...)
```

可以直接借鉴的部分：

- `--viewer auto/native/viser` 的参数语义。
- `auto` 通过 `DISPLAY` 或 `WAYLAND_DISPLAY` 判断本机是否有显示环境。
- `native` 使用 `NativeMujocoViewer`。
- `viser` 使用 `ViserPlayViewer`。
- 录视频时才使用 `render_mode="rgb_array"`。

不能直接照搬的部分：

- 不能把 `NativeMujocoViewer(env, policy).run()` 直接放进训练入口。
- 不能让 viewer 在训练时自己调用 `env.step()`。
- 不能把 `play=True` 的回放环境当作训练 runner 正在采样的环境。

因此本项目的最终方案是：借鉴参考项目的 viewer 后端选择，但训练实时同步通过 `TrainingViewerHook + env.step monkey-patch` 完成。

| `legged_mjlab/utils/helpers.py` | 增加 `--viewer_interval`、`--viewer_exit`，并把 `--viewer` help 改成 train/play 通用 |
| `legged_mjlab/utils/task_registry.py` | 训练 viewer 使用 `render_mode=None`；视频录制才使用 `rgb_array` |
| `legged_mjlab/scripts/play.py` | 保留为策略观看和调试入口，不作为实时训练 viewer 的主路径 |

完成这些改动后，用户就可以像 `legged_gym` 一样启动：

```bash
source .venv/bin/activate
python legged_mjlab/scripts/train.py --task him_go2 --num_envs 1 --viewer native
```

并且看到的就是正在训练中的 `him_go2` rollout。
